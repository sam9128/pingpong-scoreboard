# 乒乓球記分板

依 ITTF 正式比賽規則計分的單打記分板。可安裝成 PWA 離線使用，計分後會語音播報，也支援語音計分。

針對「平板橫向架在球檯旁」的情境設計：深色高對比、超大分數、整片球場區都是點擊得分區、螢幕不休眠。

## 規則實作對照

引擎完全依 ITTF Handbook 2021 v2 第 2.11 ~ 2.15 條與 3.4.4 條實作，每一條都有對應的單元測試。

| 規則 | 實作位置 |
| --- | --- |
| 2.11.1 一局 11 分、10:10 後淨勝 2 分 | `isGameOver()` |
| 2.12.1 三／五／七局制 | `gamesNeeded()` |
| 2.13.1 猜先（先發、先接、選邊） | 設定畫面 |
| 2.13.3 每 2 分換發；deuce 與輪換發球法改為每 1 分 | `serverAt()` |
| 2.13.6 上一局先發者，下一局先接 | `gameFirstServer()` |
| 2.13.7 每局換邊；決勝局一方先到 5 分再換一次 | `leftPlayerAt()` |
| 2.14.3 已得分數全部有效 | 事件溯源架構，Undo 只砍事件不改分數 |
| 2.15.1 滿 10 分鐘啟動輪換發球法 | `expediteDue()` + 局計時器 |
| 2.15.2 該局合計已達 18 分則不啟動 | `expediteAllowed()` |
| 2.15.3 球是否在比賽中決定誰先發 | `EXPEDITE_ON` 事件的 `ballInPlay` |
| 2.15.4 接發方回擊 13 板得分 | 回擊計數器，滿 13 板自動判給接發方 |
| 2.15.6 啟動後延續到本場結束 | `expediteInForce` |
| 3.4.4.1.2 每 6 分擦汗間歇 | `towelBreakDue` |
| 3.4.4.2 每方每場一次 1 分鐘暫停 | `canRequestTimeout()` + 倒數對話框 |

## 操作

| 動作 | 方式 |
| --- | --- |
| 得分 | 點擊該方的半邊畫面 |
| 該方減 1 分 | **雙擊**該方半邊畫面（僅限本局）；扣分後 5 秒內可一鍵「取消扣分」 |
| 復原／重做 | 設定面板內，或鍵盤 `Z` / `Y` |
| 得分（鍵盤） | `←` 左方得分、`→` 右方得分 |
| 輪換發球法回擊計數 | 點擊計數器，或鍵盤空白鍵 |
| 進階設定 | 右上角的 ⚙ |

畫面上沒有下方工具列。**除了選手名與比分，其餘元件一律絕對定位、不佔版面高度**：局數面板（上方中央）、計時與 🔊 / 🎤（右上）、暫停鍵（各半場下方中央）、結束對局 ✕（下方中央）、設定 ⚙（右下）。比分因此能吃滿整個球場區。誤觸的最快修正方式是**雙擊該側扣 1 分**，不需要開面板。快速連續得分有機會被誤判成雙擊，因此扣分後會跳出 5 秒的「取消扣分」提示。

⚙ 面板內容：

- **復原上一個動作／重做**
- **語音播報** 開關
- **語音計分** 開關（瀏覽器不支援時自動停用並說明原因）
- **播報聲音**：列出裝置上所有可用語音，中文排前面，其餘歸在「其他語言」。預設為自動挑選，選項會標出實際挑到哪一個
- **語速**：0.6× ~ 1.6×
- **試聽播報**：以目前設定念一句「8 比 5，○○○ 發球，局點」；改語音或放開語速滑桿時也會自動試聽
- **自訂語音計分指令**（可摺疊）：左方得分／右方得分／撤銷／暫停／明確計分詞，每項可填多個說法
- **全螢幕並鎖定橫向**（瀏覽器不支援時會提示手動轉向）
- **啟動輪換發球法**（不符合 2.15.2 條件時自動停用）
- **結束並開新比賽**

畫面上沒有頂端列。**局次、局數與換發模式集中在中央面板**；計時、🔊 / 🎤 狀態指示燈與 **⚙ 設定鍵**都在右上角，右下角因此空出來讓暫停鍵能置中於數字下方。

🔊 / 🎤 只是狀態指示燈（亮起代表開啟中，收音時呼吸閃爍），開關在 ⚙ 面板裡。

## 畫面資訊

- **版面**：三欄（球場／局數面板／球場）。面板是版面中真正的一欄並靠上對齊，因此兩側比分自然**置中於「面板邊界～畫面邊界」之間**。直向時改為三列。
- **局數**：面板中央，字級固定為比分的 **50%**。兩個數字各自用該選手的身分色。
- **選手識別**：不顯示姓名。每一側從**畫面外緣淡入一層該選手顏色的色暈**，與面板上的局數數字同色，換邊時跟著選手走。
- **賽制**：數字下方一排小圓點，**圓點總數＝取勝所需局數，實心＝已贏局數**。BO5 是三顆、BO7 是四顆，一眼看出還差幾局，因此面板上不再寫「五局三勝」這種文字。
- **比分**：畫面上最大的字，兩側各佔滿整個半場（局數搬到中央後，字級再放大一級）。
- **第幾局**：中央面板最上一行。
- **換發模式**：「每 2 分換發」是常態，不值得常駐佔版面，所以平常不顯示。只有 deuce（10:10）與輪換發球法這兩個**每 1 分換發**的例外狀態，才在「第 N 局」旁亮出主色實心徽章。徽章不寫原因 —— 10:10 比分本身就看得到，輪換發球法則有底部常駐的 13 板計數列。
- **計時 / 語音狀態**：右上角浮動 HUD。
- **球權**：發球方的色暈**加深**（不透明度 0.16 → 0.68）並鋪滿整個半場，延伸範圍持續呼吸 —— 濃度不變、只動範圍，用 `background-size` 補間（`linear-gradient` 的停止點在沒有 `@property` 的瀏覽器無法平滑補間）。呼吸用 `alternate` + 對稱的 ease-in-out（`--ease-breath`），兩端速度歸零，不會像 expo-out 那樣衝出去再急停。不使用外框或輝光。
- **局數面板**：毛玻璃（`backdrop-filter: blur(26px) saturate(150%)`），底下的身分色暈會透上來。
- **色暈不會被欄位切斷**：`::before` 往中央多延伸半個球場寬，因此是自然淡出到中間，而不是在欄位邊界硬切。

## 裝置適配

- **平板橫向**（主要情境）：比分基準 `--score-size` 為可用高的 50% 與可用寬的 27.5% 取小，1024×768 下為 **282px**、局數 **141px**。
- **手機橫向**：改為可用高的 60% 與可用寬的 28% 取小，844×390 下為 **234px**。
- **瀏海／鏡頭挖孔**：可用寬高會先扣掉 `env(safe-area-inset-*)`，因此比分永遠不會被推到鏡頭底下（844×390、左側 44px 挖孔時降為 209px）。
  安全區內距放在 `#courtL` / `#courtR` 上而非 `.courts`，有兩個理由：一是球場本身仍然滿版，兩側色暈可以一路畫到實體螢幕邊緣，鏡頭區不會留下一條沒上色的黑邊；
  二是暫停鍵是絕對定位在 padding box 的 50%，內距左右對稱時它才會與置中於 content box 的比分對齊。
- **直向**：平板直向改為上下分割，局數面板移到正中央的交界處。
- **手機強制橫向**：手機直向（寬度 540px 以下）會蓋上一層「請轉為橫向」提示。瀏覽器無法替使用者轉螢幕 —— Screen Orientation API 的 `lock()` 必須先進入全螢幕，iOS Safari 更是完全不支援 —— 因此採三層做法：manifest 宣告 `orientation: landscape`（Android 安裝後生效）、開賽時 best-effort 呼叫 `lock()`、以及這層一定會生效的覆蓋提示。設定面板另有「全螢幕並鎖定橫向」可手動觸發。
- **開賽時自動全螢幕**：按下「開始比賽」時，觸控裝置（`pointer: coarse`）會順帶送出 `requestFullscreen()`。這不只是為了畫面乾淨 —— Android Chrome 只有在全螢幕或已安裝的 PWA 才會把內容畫進鏡頭挖孔區，一般分頁一律補黑邊；`orientation.lock()` 同樣要求全螢幕。桌機刻意不自動全螢幕，被瀏覽器擋下也只是靜默略過，設定面板裡仍有手動入口。

## 設計系統

深色 Linear / Modern 風格。所有 token 集中在 `src/ui/styles.css` 的 `:root`，元件只消費變數，不寫死顏色。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-base` / `--bg-deep` | `#050506` / `#020203` | 近黑底色，不使用純黑 |
| `--fg` / `--fg-muted` | `#EDEDEF` / `#8A8F98` | 主文字 / 次要文字 |
| `--accent` | `#5E6AD2` | **球權**外框與輝光、主要按鈕、focus ring |
| `--p1` / `--p2` | `#E5A33D` / `#4FD1C5` | 選手身分色，刻意遠離主色以免與球權混淆 |
| `--danger` | `#E5484D` | 賽末點 |
| `--score-size` | `min(50vh, 27.5vw)` | 比分基準尺寸。局數 = 50%、分隔號 = 34%、圓點 = 5.5%、設定鍵 = 19%，只要調這一個值整組比例就跟著走 |

幾個刻意的取捨：

- **球權指示比設計系統的預設更強烈。** 系統原則是邊框近乎隱形（6–10% 白），但球權是功能性指標，必須在數公尺外一眼辨識，因此用了 3px 實色外框加多層輝光。
- **狀態不只靠顏色區分。** 球權是「外框 + 輝光」，換發模式是「實心徽章」，兩者在形態上就不同，符合色彩獨立性要求。
- **背景光暈尊重 `prefers-reduced-motion`。** 三顆大範圍模糊光暈在低階平板上可能耗電，關閉系統動態效果後動畫即停止。
- **不載入外部字體。** Inter 若系統已安裝就會用上，否則回退到內建中文字體 —— 這是為了讓 PWA 離線時排版不會跑掉。
- **不做任何 hover 效果。** 設計系統原本有游標追蹤聚光燈與各種 hover 態，但目標裝置是平板與手機：觸控上 `:hover` 沒有意義，而且點擊後樣式會殘留。保留的是 `:active` 按壓回饋與 `:focus-visible` 焦點環。

## 本地儲存

兩份資料分開存放在 `localStorage`，清除比賽不會洗掉設定：

| Key | 內容 | 何時寫入 |
| --- | --- | --- |
| `pingpong-scoreboard/v1` | 賽事的完整事件串 + 賽事設定 | **每一次變動**（得分、暫停、啟動輪換發球法、復原、扣分）都立即寫入 |
| `pingpong-scoreboard/prefs/v1` | 上次使用的選手名、賽制、猜先、起始方位、播報與語音計分開關、**播報語音與語速**、**自訂計分指令** | 開賽時與每次調整設定時立即寫入 |

因為採事件溯源，賽事記錄存的是**所有變動的完整歷程**而不是當下比分，因此關掉分頁後回來按「繼續上一場」，連復原歷史與輪換發球法的啟動時機都會一併還原。

下次開啟時，設定畫面會自動以上次的選項預填。

讀取端對兩份資料都做格式驗證，欄位缺漏或損毀時退回預設值，不會讓畫面壞掉。指定的播報語音若在另一台裝置上不存在（例如換機），會自動退回自動挑選而不是變成無聲。

## 語音

**播報**（`SpeechSynthesis`）：依裁判習慣先報發球方分數，例如「8 比 5，王小明 發球」，並在局點、賽末點、換邊、局末、賽末時加報。iOS 需要先點過畫面一次才會發聲，因此播報從「開始比賽」那一下才解鎖。

**語音計分**（`SpeechRecognition`）：

- 預設指令：`左邊得分` / `右邊得分` / `左` / `右` / 選手姓名 / `取消` / `撤銷` / `左邊暫停`
- **全部可在設定中改成自己習慣的說法**，例如把左右改成「紅方／藍方」、把撤銷改成「喊卡」。用「、」或逗號分隔多個說法；某一項清空即還原該項預設，不會讓整組指令失效
- 選手姓名永遠可用，不需另外設定；姓名優先於左右，因為換邊後左右會變、姓名不會
- 句子含「明確計分詞」（預設是得分、加分…）時一律採信；否則只接受 6 字以內的短句，避免場邊閒聊誤觸
- 每次語音計分後會跳出 5 秒的撤銷提示
- 播報期間自動關閉收音，避免播報聲被自己聽成指令

### 語音計分的限制，請先了解

- **Chrome / Edge / Safari 支援，Firefox 不支援。**
- **多數瀏覽器是把音訊送到雲端辨識，需要網路連線。** 安裝成 PWA 後其他功能都能離線運作，但語音計分在離線時會失效。
- 球館噪音大，語音只是輔助，主操作永遠是點擊畫面。

## 開發

```bash
npm install
npm run dev      # 本機開發伺服器
npm test         # 規則引擎與語音指令比對的單元測試
npm run build    # 型別檢查 + 產出 dist/
npm run preview  # 預覽正式建置結果
node scripts/make-icons.mjs   # 重新產生 PWA 圖示
```

## 部署到 GitHub Pages

1. 建立名為 `pingpong-scoreboard` 的 repo 並推上 `main`。
   repo 名稱若不同，請一併修改 `vite.config.ts` 裡的 `REPO` 常數，否則資源路徑會 404。
2. 在 repo 的 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
3. 推送後 `.github/workflows/deploy.yml` 會自動跑測試、建置並發佈到
   `https://<帳號>.github.io/pingpong-scoreboard/`。

## 安裝到裝置

用瀏覽器開啟上述網址後：

- **Android / 桌面 Chrome**：網址列的「安裝」圖示，或選單 →「安裝應用程式」
- **iPad / iPhone Safari**：分享 →「加入主畫面」

安裝後會全螢幕橫向啟動，並可離線使用（語音計分除外）。

## 架構

事件溯源：唯一的真實來源是 `MatchEvent[]`，比分、發球權、方位全部由 `reduce()` 重算。

因此 Undo 只是砍掉最後一個事件、續賽只是把陣列存進 `localStorage`，而規則測試只要「給一串事件、斷言狀態」就能寫。

```
src/
├─ rules/          純邏輯，零 DOM 依賴
│  ├─ types.ts     資料模型
│  ├─ engine.ts    reduce() 與所有規則函式
│  └─ __tests__/
├─ ui/
│  ├─ app.ts       畫面控制器
│  └─ styles.css
├─ audio/
│  ├─ tts.ts       語音播報
│  ├─ stt.ts       語音辨識與指令比對
│  └─ __tests__/
├─ store.ts        localStorage 續賽
└─ wakelock.ts     螢幕恆亮
```
